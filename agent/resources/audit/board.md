# 黑板

用 `board_read` 看总览、焦点、局部依赖或证据；用 `board_update` 批量记录有决策意义的变化。

- 新条目省略 id，写 question 和明确的 binding。之后用 `changed` 返回的 Q 编号更新。普通条件核查补入原条目。
- 用 `capture` 保存实际工具结果及查询来源，注明支持、反证或前沿角色。持久 E 编号在 `captures` 中返回。即使条目仍为 `pending`，其中的工具观察也应直接关联原始证据。可在 `evidence` 中复用已有 E 编号。
- 整份查询或字节码页 capture 时省略 ids；只有 path 指向带数字 id 的记录数组时才用 ids 选取，例如扫描的 `path:["relations"]`。数字不是数组下标，也不是持久 E 编号。
- 不预填或猜测 Q/E 编号。新条目可在同一更新中 capture 真实引用：`{"changes":[{"question":"具体问题","binding":"对象/参数/路径范围","capture":[{"resultRef":"工具实际返回的引用","role":"support"}]}]}`。确认返回编号后再更新判断；`success` 和 `dead` 还需 reason 与实际字节码/连接支持。
- 大扇出用候选集合和前沿引用承接。按需分页，不把分组当作对象或路径等价。
- `dependsOn` 只组织问题；实际必要与替代支持读取 Scanner 证据，不自动传播结论。
- `open` 可继续；`pending` 写缺项；`dead` 写具体反证；`success` 须通过 `verify`，写可报告链的现实入口、触发、完整绑定、危险影响与成立条件。后两者需实际字节码或连接核查支持；持久化门槛不代替语义核查，局部能力不标 `success`。
- 相同条件可引用已有证据；不同绑定分别保留。状态可以重新打开，焦点切换不改变结论。
- `board_read` 的证据是持久快照；旧结果引用和 loader 编号只属于原运行。恢复后先读黑板，新的查询使用当前目标，不能把旧编号当作新编号。
- 恢复时若证据带 `unavailable`，从 `part: source` 查看失效原因，补查或修复后重新打开；原理由和用户条件会保留，失效证据不能作为收尾依据。
