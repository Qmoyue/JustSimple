# 审计报告

以危险反序列化审计发现组织 Markdown。调用 `write_report` 提供总览、已查范围和发现条目；每项引用当前快照中的黑板条目，写清影响、代表链路、成立条件和修复方向。

读取黑板及持久证据核实来源。普通条件作为支持，不单独升级为漏洞；实际入口、对象与参数绑定、支持选择和字节码位置须能对应。未知项写入未决，禁止把静态候选描述为动态复现。
每项发现必须通过 `verify`：说明外部输入能力、恢复触发、完整链、关键参数控制、现实部署条件及实际影响；没有证据的关键前提不能靠措辞补齐。理论连接、单纯危险 API 命中和苛刻不可用链留在未决或具体排除说明中，不凑发现数量。
报告面向使用者简洁表达，不逐项照抄核查表或反复重述同一条链与条件。修复方向紧扣实际入口和危险行为，不堆叠无依据的环境假设、防护选项或已弃用机制；少量代表位置与证据引用足够，完整原文由附件承接。

无发现时使用空 findings，说明范围和未决。报告自动附条目版本、证据文件、查询来源与输入身份。若需补查，先用 `audit_phase` 恢复探索，完成后再次收尾。
