# 探索与核查

- 明确目标、入口、依赖、JDK 与可选输入；先定位值得判断的危险操作或关键连接。
- 图给出符号连接，核对实际指令、接收者、完整参数绑定、loader 和互斥路径。知识是搜索参考，按当前结构核对。
- `find_symbols` 的 query 是方法标识的字面子串，不是通配符或字段搜索。默认 `target` 只搜目标类，`candidates` 加入依赖和静态定义类，均不枚举 JDK；读 JDK 类型须指定精确 owner。空搜索不能推断未搜索的类库缺失。指定 owner 取得 `value.classes` 中父类、接口、访问标记及字段，用于核对可恢复性与 transient 状态。
- 符号与字节码查询针对当前类声明的方法。没有声明不等于没有继承实现；用 `resolve_dispatch` 核查接收者，取得实际声明 owner 后再读方法，尤其是接口默认方法。
- 工具预览只是已保存结果的一小段，先沿同一 resultRef 用 `scanner_read_result.next` 读完。字节码还有方法切片：`inspect_method.summary.offset/next` 是 ASM 指令范围，切片读完且 summary.next 非 -1 时，用它再次 inspect；新引用的 instructions 数组从下标 0 读起，不能传入 ASM 位置。可按需要提高 characters，避免用默认小页反复读长方法。
- 扫描引用的 findings/relations/breakpoints/inputRequirements 在顶层，查询引用的数据在 value；不清楚时省略 path 查看键名，不猜路径反复试错。
- 遍历、分派扇出和来源追踪用工具批量完成；根据范围、实际消耗和剩余前沿决定继续、改向或暂缓。
- 默认预算不是硬性探索总额。可主动增大单次预算，或用图 cursor、剩余接收者、来源 frontier 和精确入口分批续查；完整扫描加预算会重新计算，先判断定向查询能否解决断点。显式宿主上限、页大小和结果容量用分批与释放处理，不假装已经查完。
- 不使用机械重试消耗 token：每次续查说明要补的具体缺口；同样输入、范围和预算没有新事实时复用结果。关键证据先 capture，再通过 `scanner_read_result` 的 release 释放不用的临时引用；不得释放仍需 scanRef 查询的扫描结果。
- 对重要连接核查所选支持。替代支持分别考虑，`CLOSED` 说明所选支持闭合，输入可控性和部署条件仍须各自说明。
- 工具未支持或与你的字节码理解冲突时，保留原输出和具体位置，记录解释及未决，不修改工具事实。
- 正反证按具体对象和路径限定。保留候选与断点，不运行目标或构造攻击输入。
