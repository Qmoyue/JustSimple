# 交互审计

选好目标和类库后，用 `/agent` 进入审计。可以从一次完整扫描的结果开始，也可以直接问一个要核对的问题。Agent 用分析工具查看指令、调用关系和数据来源，再把静态依据、当前判断和待补条件分别记下来。[启动与模型设置](../usage.md#agent)

## 黑板与恢复

黑板围绕问题组织记录。用 `/board` 查看焦点、已找到的证据和还需查证的事项。展开范围较大时，黑板保留已查范围和续查位置，详细证据按引用查看。

| 状态 | 含义 |
| --- | --- |
| `open` | 可以继续核查 |
| `pending` | 还缺输入、依赖或证据，或需要继续扩大分析范围 |
| `dead` | 当前范围内已有具体依据可以排除 |
| `success` | 依据和前提齐备，可以写入报告 |

关键证据会保存所选内容及查询来源。临时引用随分析进程结束而失效，保存的依据可随任务重新打开。用 `/resume` 恢复会话后，再用 `/agent` 恢复分析工具。工具会核对输入和保存的证据，缺失或失效的依据会标明原因，对应条目留作待查。

## 报告

收尾时固定一份黑板与证据快照。报告按这份快照整理发现，写明依据、成立前提、尚未覆盖的范围和修复方向。每项发现可回查到当时的条目和证据。后续补查可以从任务继续，再生成新版本。

报告保存在状态目录下的 `tasks/`，每次发布使用任务中的 `reports/revision-<版本>/`。目录里的 `report.md` 可直接阅读，旁边保存输入说明、黑板快照和证据附件。[Scanner 报告格式](evidence.md#扫描报告)
