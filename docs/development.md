# 构件开发约束

通用约束见仓库根目录的 [AGENTS.md](../AGENTS.md)。三个构件共享[证据契约](reference/evidence.md)，目标只作为静态数据读取。

## Scanner

- Scanner 管理程序事实和分析语义。CLI 与局部查询复用公共 API，TUI 和模型策略由 Agent 管理。
- 将目标字节码与静态数据作为输入读取。分析过程不执行目标类、流或回调，也不生成攻击字节流。
- 知识只引导探索。对象、调用和支持取自本次输入，保留完整调用元组、加载范围与互斥路径。分析按通用语义推导。
- 未知、缺依赖和预算耗尽保留为未决。排除绑定需要反证，可能别名与确定同一对象分别处理。
- 仅合并语义兼容的事实。条件核验、堆可见性和候选收尾复用同一份语义。
- 样例只编译和读取。验证正反条件与证据，分别核对候选召回和连接准确性。

## Bridge

- Bridge 管理协议、参数校验、输入与结果资源。它通过 Scanner 公共 API 查询，薄 JAR 与同次构建的 Scanner 配套。
- 结果保留输入范围、证据归属和查询状态。预算、分页和容量按[工具契约](reference/evidence.md#工具查询)校验。
- 创建者负责取消和关闭，失败时清理未完成结果。UTF-8 协议错误保留上下文并结束调用。

## Agent

- Pi 管理模型、认证、思考设置、会话、纠偏和上下文压缩。Agent 管理终端页面、扫描偏好、工具权限和目标生命周期。
- 界面从各自的状态所有者派生，审计编排管理阶段权限。模式切换、取消、恢复和审计阶段的执行权限与界面保持一致。
- Agent 决定查询方向和预算，通过 Bridge 复用 Scanner 的分析。工具返回有界结果与引用。
- 黑板服务管理条目、持久证据和快照。工具与界面通过服务访问，报告按[溯源契约](reference/audit.md#报告)取材。
- 运行期指令和报告模板由 Agent 按需加载。模型只访问获准的内置资源和当前范围内的证据。
- 用根目录的 pnpm 配置和锁文件管理依赖。安装脚本、pnpmfile 钩子和脚本缓存保持关闭。
- 集成测试使用配套的 Scanner 和 Bridge JAR，覆盖实际交互、工具限制、取消和结果引用生命周期。
